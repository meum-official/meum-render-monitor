# MEUM WATCH — 공개 화면 렌더링 모니터

운영 공개 페이지를 새 익명 브라우저에서 열어 필수 본문·로딩 종료·이미지·실행 오류·HTTP·가로 넘침을 확인합니다. 데스크톱 1440×1000과 모바일 390×844를 구분하며 기존 공개 대표 표본을 검사합니다. 전체 전시 전수 검사는 아닙니다.

## 실행 범위

`config.json`의 `renderOnly=true`가 기본입니다. 이 모드는 기능 설정이 남아 있어도 메뉴 여정·입력·제출·클릭·생성·수정·초대·결제·인증 업무를 실행하지 않습니다. 업무 11개는 **대상 아님**이며 성공·실패 집계에서 제외합니다. 로그인 화면 표시는 인증 성공을 뜻하지 않습니다.

직접 문서 열기, 준비 대기, 처음 세 화면 높이까지 제한된 스크롤만 수행합니다. 접힌 설명·팝업·입장 안내를 클릭하지 않습니다. 관측 범위를 넘는 본문과 상호작용 이후 상태를 검증했다고 주장하지 않습니다.

모든 비 GET/HEAD 요청과 WebSocket, 알려진 부작용 GET을 차단하며 backend 요청은 검토된 공개 조회 허용 목록으로 제한합니다. 개인 작업공간·사용자 인증 API는 허용하지 않습니다. 서버의 일반 HTTP 방문 로그까지 발생하지 않는다는 뜻은 아닙니다. Unity 입장에 필요한 POST·세션·소켓이 차단되면 장면은 미확인입니다. 제한을 우회하거나 장면을 정상 처리하지 않습니다.

## 기준과 디자인 변경

- 정상: 해당 본문의 필수 요소·준비·픽셀 조건을 관측 범위에서 만족했습니다.
- 실패: 실제 문서/필수 자산 오류, 독립 실행 오류, 빈 화면·로딩 잔존·필수 본문 누락·가로 넘침 등의 근거가 있습니다.
- 미확인: 정책 차단, 기준 미등록, 캡처/이미지 로딩 미완료, 접근 안내, 기준 버전 불일치 등이 남았습니다. 정상으로 합산하지 않습니다.

`contracts.mjs`의 페이지별 준비·오류 계약과 `render-mode.mjs`의 의미 기반 요소를 재사용합니다. 장식용 클래스 계층 대신 안정적인 본문 ID·페이지 영역·`data-page`/`data-render` 표식을 우선합니다. 공통 헤더만으로 통과하지 않습니다. 게시판 빈 상태는 본문 안의 보이는 문구가 있는 `[data-render-state="empty"][role="status"]`처럼 명시적 상태가 있어야 합니다. 빈 DOM을 정상 빈 상태로 추측하지 않습니다. 모바일에서 숨기는 열 제목은 본문 필수 기준으로 사용하지 않습니다.

색·간격·장식·배치 변경에는 의미 계약을 유지합니다. 핵심 영역 추가/삭제·빈 상태·반응형 대체 요소 변경은 제품 변경 검토와 함께 계약 차이를 검토합니다. 새 경로는 등록 전 미확인입니다. 전체 소스를 AI로 매번 비교하거나 관측 화면을 자동으로 새 정상 기준으로 채택하지 않습니다.

## 버전과 캡처

명세 해시와 증거가 있는 모니터 커밋을 기록합니다. CI는 `GITHUB_SHA`를 사용하며 로컬에서 증거가 없으면 unknown입니다. 제품 소스/운영 배포 커밋은 현재 검증 연결이 없어 **unknown**입니다. 배포 변경 감지용 자산 fingerprint를 제품 커밋으로 표시하지 않습니다. 버전 동일성이 미확인이어도 HTTP·DOM·이미지 관측 사실은 별도로 보존합니다.

향후 기존 8301 release receipt·아카이브 release manifest와 실제 운영 자산을 대조해 배포 증거를 연결해야 합니다. 기준 불일치는 서비스 장애와 분리하며 실제 HTTP/실행 오류를 숨기지 않습니다. 배포 변경 시 이전 결과를 무효화하는 기존 구조를 유지합니다.

`captureScreenshots=false`가 기본이며 픽셀은 메모리에서 확인합니다. 공개 보고서에는 캡처·고객 제목·요청값·콘솔 원문·인증정보를 게시하지 않습니다. 콘솔은 오류 개수만 기록하고 독립적인 pageerror는 별도 실패 처리합니다. 로컬 캡처를 켜도 자동 기준 채택이나 공개 게시를 활성화하지 않습니다. 민감·인증 화면 캡처를 추가하지 마세요. 새 시각 기준은 비교 자료를 검토한 뒤 명시적으로 채택합니다.

## 로컬 검사

Node.js 22 이상과 설치된 Chromium 또는 Windows Edge가 필요합니다.

```sh
npm ci --ignore-scripts
npm run install:browser
npm test
npm run test:browser
node ci.mjs self-test
```

테스트는 합성 localhost 화면·메모리 자료를 사용합니다. `npm start`는 127.0.0.1:8310 대시보드와 공개 사이트 scan을 시작하고, `npm run scan`은 공개 사이트를 한 번 검사합니다. 테스트와 운영 scan을 구분하세요.

종료 코드 0은 이번 범위 렌더링 통과, 1은 관측 실패, 2는 미완료·미확인입니다. 미확인을 없애려고 검사 기준을 자동 완화하지 않습니다.

## 기존 Actions와 게시

기존 render-check.yml의 권한·스케줄·Pages 게시 방식을 유지하고 `MONITOR_RENDER_ONLY=1`로 범위를 강제합니다. 합성 회귀 후 scan하며, 검사 실패·미확인도 보고서를 내보내고 최종 job 실패 신호를 보존합니다. 공개 캡처 업로드·새 credentials/secrets/권한은 추가하지 않습니다.

push·Actions 실행·외부 게시는 사용자에게 승인된 범위에서 수행합니다. 제품 백엔드/8301/8302 배포·마이그레이션·DB 변경은 별도 작업입니다. 로컬 통과를 Actions·운영 검사 완료로 보고하지 않습니다.

## 보존된 선택 fixture

기존 업무 fixture는 보존하되 렌더링 실행에서 호출하지 않습니다. 별도 fixture의 제품 소스는 절대 경로 `MEUM_PRODUCT_ROOT`로 명시하며 이관 전 계층을 추측하지 않습니다. 등록된 모니터 fixture 자체는 현재 저장소에서, 제품 파일은 지정한 제품 루트에서 찾습니다. 환경 파일이나 임의 파일은 source proof 대상으로 허용하지 않습니다.

제품 루트 지정은 실제 앱·DB 격리 증명이나 운영 인증 승인이 아닙니다. 기본 렌더링 테스트에는 제품 체크아웃·테스트 계정·비밀번호가 필요하지 않습니다.
