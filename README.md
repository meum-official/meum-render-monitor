# MEUM WATCH — 공개 대표 표본 검사

믐과 별도의 Chromium 브라우저로 공개 화면을 읽기 전용 검사합니다. 이번 배포 범위는 캡처 실패 분리, 대표 표본 선택, 경량 결과 게시입니다. 이전 로컬의 인증 업무·기능 확장 파일은 이 출시 체크아웃에 포함하지 않습니다.

## 범위와 판정

- 프리뷰: 공개·진행 중·비인증 입장이 확인된 일반 전시 무작위 최대3개.
- 초대장: 같은 선택 전시의 실제 공개 Hashids 최대3개. ID·소개 응답·관람 입장 상태를 대조합니다.
- 관람: 공개 전시 최대3개. 공개 사이트맵과 별도 보존 기간을 확인한 아카이브가 있으면 이 한도 안에서 한 자리를 배정합니다. 일반 표본이 없으면 실제 room_id와 공개 입장을 확인한 큐레이터 전시1개만 대체합니다.
- ID 없는 정적 페이지는 유지합니다. 제작자·아카이브 소유자·웹툰 같은 별도 공개 경로는 유형별 대표1개를 남깁니다.
- 원데이·샘플 초대장처럼 별도 입장 조건을 입증하지 못한 유형은 샘플 없음/미검증으로 기록합니다. 아카이브도 공개 증명이 없으면 미검증입니다. 일반 전시의 통과로 대신 완료하지 않습니다.

전체 전시를 렌더링하는 검사가 아닙니다. 공개 목록의 최대2페이지에서 후보를 모으고 최대12개 후보의 공개 입장을 확인합니다. 후보 수·선언된 전체 수·읽은 페이지 수·수집 한계는 보고서에 남깁니다. 제한된 후보 집합에서 고르므로 전체 전시의 균등 표본을 보장하지 않습니다.

사이트맵·추가 페이지가 다른 전시 ID를 다시 넣지 못하게 제한합니다. 실행별 seed·선택 ID·실제 해시·URL·선택 이유를 고정하고, 같은 실행 재개에서는 새 전시로 바꾸지 않습니다. 선택 전시가 비공개·종료·삭제 등으로 부적격이 되면 제외 사유와 미확인을 기록합니다.

초록은 이번 표본의 등록된 렌더 조건 통과, 빨강은 입증된 페이지 오류, 회색은 미점검·차단·오래된 결과·미등록·픽셀 미확인입니다. **실제 앱 업무11개는 모두 별도 blocked**이며 표본 통과와 합치지 않습니다. 실제 계정 권한·저장·설문·결제 검증은 이번 공개 검사 범위에 포함하지 않습니다.

## 캡처 실패와 공개 정보

`captureScreenshots` 기본값은 false입니다. 픽셀 검사는 메모리 PNG로 수행하고 파일을 기본 저장하지 않습니다. 메모리 캡처 자체가 실패하면 픽셀은 미확인으로 표시하고 HTTP·DOM·실행 오류 결과를 계속 남깁니다. 이미 확인된 JavaScript/HTTP 오류를 정상으로 바꾸지 않습니다.

로컬에서 파일 저장을 명시적으로 켜도 저장 실패가 핵심 검사를 중단시키지 않습니다. export의 캡처 복사 실패도 생략 사유만 남깁니다. 운영 CLI의 공개 결과에는 PNG를 포함하지 않습니다. 선택적 업로드 실패가 필수 결과 게시를 막지 않는 경로는 모의 quota 실패로 검증합니다.

공개 JSON은 작은 허용 목록으로 만듭니다. 이번에 명시 승인된 공개 표본 ID·공개 해시·등록된 URL과 선택 범위는 표시하되, 고객 제목·답변·자격증명·원본 오류·관측 객체·임의 쿼리는 게시하지 않습니다. 제작자 등 공개 경로 식별자는 숨기고 익명 행으로 검사 결과를 유지합니다.

모든 nonGET/HEAD 요청과 WebSocket을 차단합니다. 소스에서 확인한 카운터 보정·만료 전시 닫기·기본값 생성·데이터 마이그레이션 등 쓰기 동작이 있는 GET/HEAD도 차단합니다. 이 차단은 메타데이터 조회와 브라우저 내부 요청에 함께 적용합니다. 모든 GET의 무해성을 보장하는 것은 아니며, 공개 방문에 따른 일반 서버 로그는 발생할 수 있습니다.

외부 분석 요청 차단은 별도 정책 수로 기록하며 그것만으로 정상 렌더를 미확인 처리하지 않습니다. 서비스의 필수 요청을 차단해 확인하지 못한 화면은 제한을 표시합니다.

## 결과 게시와 실제 실패 원인

기존 [실패 실행](https://github.com/meum-official/meum-render-monitor/actions/runs/40794457754)은 Pages 업로드·배포와100MB 검사에 성공했습니다. 최종 검수 단계에서 공개 목록339/340 불일치 및55분 제한으로 미점검 항목이 남아 scan 종료코드2를 기록한 것이 실패 원인이었습니다. 캡처 용량 한도 실패로 추정하지 않습니다.

현재 워크플로는 Actions artifact/cache 업로드와 삭제 단계를 사용하지 않습니다. `index.html`, `app.js`, `style.css`, `status.json`, `.nojekyll`, `.monitor-ci.json`만 `main:/docs`에 커밋하고 Pages 빌드를 명시 요청합니다. 같은 보고서 커밋의 빌드가 built가 될 때까지 확인합니다. 기존 main 전용 배포 접근 정책을 변경하지 않습니다.

검사 실패/미완료라도 경량 결과를 게시하고, 최종 job에는 그 실패를 유지합니다. push 성공만으로 게시 성공으로 보고하지 않습니다. 권한 거부·push 충돌·연결 불확실·빌드 대기 등은 `data/publication-error.json`으로 구분합니다. 기존 artifact 영구삭제·유료 플랜 전환은 하지 않습니다.

재개 상태는 공개 `docs/status.json`과 `docs/.monitor-ci.json`에서 복원합니다. 원본 data·캡처·인증 정보를 캐시하지 않습니다. 첫 실행은 두 파일이 모두 없을 때만 인정하고 일부 누락/손상은 실패로 남깁니다. 검증된 새 target 정보와 이전 검사 결과를 합쳐 재개합니다.

## 실행

Node.js22 이상이 필요합니다.

```sh
npm ci --ignore-scripts
npm run install:browser
npm start
```

로컬 대시보드는 `http://127.0.0.1:8310`입니다. 단일 검사는 `npm run scan`입니다. 종료코드0은 이번 공개 표본의 필수 검사 통과,1은 페이지 실패,2는 미완료/미확인입니다. 전체 서비스 정상이나 실제 업무11개 통과를 뜻하지 않습니다.

GitHub Actions는 매시17분 배포 변경을 확인하고, 변경 후6시간 동안 매시간 표본을 검사합니다. 수동 `once`/`burst6h`와 repository dispatch `meum-deployed`를 유지합니다. 예약은 지연될 수 있습니다. `MONITOR_MODE=continuous`이면 매시간 검사합니다. 표준 공개 저장소 실행기와 Pages를 사용하며 유료 설정은 변경하지 않습니다.

## 검증

```sh
npm test
npm run test:browser
node ci.mjs self-test
git diff --check
```

로컬 bare Git와 모의 Pages로 artifact quota/업로드 실패,403, 충돌, 빌드 오류·대기·잘못된 SHA를 검사합니다. 브라우저 검사는 localhost 합성 페이지에서 캡처 생성 실패·저장 실패·복사 실패·실제 페이지 오류 보존·공개 요약 UI·표본 재개를 확인합니다. 실제 GitHub Actions/Pages 검증은 별도 실행 URL과 코드·게시 SHA로 기록합니다.

`.env`, `data/`, `site/`, `node_modules/`는 커밋하지 않습니다. 같은 데이터 폴더의 동시 실행은 금지합니다. 잠금 파일이 남으면 기록된 PID가 종료됐는지 확인하고 해당 잠금 하나만 제거합니다. 외부 주소로 로컬 서버를 열려면 기존 인증 또는 인증 프록시가 필요합니다.
