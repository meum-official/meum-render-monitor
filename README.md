# MEUM WATCH

믐 서비스와 별도로 공개 운영 URL을 Chromium에서 직접 여는 점검기입니다. 운영 서버, DB, 관리자 인증, 배포 스크립트를 변경하지 않습니다.

- 초록: 최근 브라우저 검사의 HTTP·실행·필수 화면·픽셀 검사를 통과했습니다.
- 빨강: 실행 오류, 흰 화면, 필수 요소 누락, 무한 로딩, 잘못된 이동, 누락 이미지 등을 발견했습니다.
- 회색: 미점검, 오래된 결과, 비밀번호/입장 안내, 검사 기준 미등록, 점검기 연결 문제입니다.

공개 사이트맵을 재귀 수집하고, 비인증 전시 목록의 페이지를 끝까지 확인합니다. 전시 프리뷰의 관람 버튼에서 실제 목적지를 수집해 3D 관람 화면도 새 게스트 컨텍스트에서 확인합니다. 목록 개수 불일치·수집 실패·실행 한도는 완료로 숨기지 않습니다. 페이지는 순서대로 열고, 긴 순회는 다음 실행에서 이어갑니다.

## 무료 클라우드 실행

이 폴더만 별도의 **공개 GitHub 저장소**에 올립니다. 믐 소스 전체를 올리지 않습니다. 표준 Ubuntu Actions 실행기와 GitHub Pages를 사용하며, 유료 실행기·Netlify·별도 서버는 필요하지 않습니다.

`.github/workflows/render-check.yml`은 매시 17분에 공개 웹 배포 파일을 확인합니다. 처음 실행하거나 배포 변경을 감지하면 6시간 동안 매시간 브라우저 점검을 실행합니다. 창이 닫히면 가벼운 배포 확인만 합니다. Actions의 `Run workflow → burst6h`로 즉시 6시간 점검을 시작하거나 `once`로 한 번 점검할 수 있습니다. 실제 시작 시각은 GitHub 대기열에 따라 늦어질 수 있습니다.

GitHub 정책상 공개 저장소에 60일간 활동이 없으면 예약 실행이 자동 중단될 수 있습니다. 이때 Actions에서 워크플로를 다시 활성화해야 합니다. [공식 정책과 재활성화 방법](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/disable-and-enable-workflows?tool=webui)을 참고하세요. 오래된 화면 결과는 대시보드에서 회색으로 표시합니다.

공개 웹 파일에 드러나지 않는 백엔드 배포는 배포 완료 후 다음 이벤트로 알립니다. 이 프로그램은 믐의 배포 절차에 이 명령을 자동으로 삽입하지 않습니다.

```sh
gh api repos/OWNER/REPOSITORY/dispatches -f event_type=meum-deployed
```

Repository variable `MONITOR_MODE=continuous`이면 24시간 매시간 점검합니다. 기본은 `after-deploy`입니다. GitHub Pages는 Actions 배포 방식으로 설정합니다. GitHub 저장소·대시보드·공개 화면 캡처는 인터넷에 공개되며 인증 정보는 포함하지 않습니다.

무료 사용을 위해 저장 상태의 캐시 개수·크기와 Pages 파일 크기를 제한합니다. 한도를 넘으면 해당 저장/배포를 중단하거나 캡처 공개를 생략하고 이유를 남깁니다. 유료 플랜이나 지출 한도를 변경하지 않습니다. 무료 제공 조건은 공급자 정책에 따릅니다.

## 집 PC에서 실행

Node.js 22 이상이 필요합니다. 이 폴더에서 처음 한 번 실행합니다.

```sh
npm ci
npm run install:browser
```

일반 실행은 60분 간격으로 계속 점검합니다.

```sh
npm start
```

브라우저에서 `http://127.0.0.1:8310`을 엽니다. 배포 후 6시간 모드는 `.env.example`을 `.env`로 복사한 뒤 `MONITOR_MODE=after-deploy`, `INTERVAL_MINUTES=60`을 추가합니다. 시작 시 현재 배포부터 6시간 점검하고, 이후 공개 배포 변경을 기다립니다. PC를 끄면 로컬 점검은 중단됩니다.

단일 순회는 `npm run scan`입니다. 종료 코드 0은 전체 등록 검사가 통과, 1은 문제 발견, 2는 목록/실행/미확인 범위가 있다는 뜻입니다. `SCAN_MAX_MINUTES`로 작업 시간을 제한하면 미완료 순회는 다음 실행에서 이어갑니다. `SCAN_LIMIT`은 개발 검증용이며 전수 검사로 보고하지 않습니다.

`config.json`에서 점검 출처·추가 페이지·데스크톱/모바일 크기·대기 시간을 지정합니다. 기본은 데스크톱 1440×1000입니다. 모바일을 추가하려면 viewports에 `{"name":"mobile","width":390,"height":844,"isMobile":true}`를 추가합니다. 새 경로의 화면 기준은 `contracts.mjs`에 등록합니다. 알 수 없는 화면은 초록으로 판단하지 않습니다.

## 검증

```sh
npm test
npm run test:browser
node ci.mjs self-test
```

브라우저 회귀 검사는 외부 서비스 없이 로컬 테스트 페이지로 흰 화면·스크립트 예외·잘못된 이동·404·누락 이미지·배경·비밀번호 화면을 검증합니다.

## 결과와 복구

실제 결과는 `data/status.json`, 캡처는 `data/screenshots/`, 최근 이력은 상태 파일에 저장합니다. `.env`, data, node_modules는 커밋하지 않습니다. 외부에서 로컬 대시보드를 열려면 인증 또는 인증 프록시가 필요합니다.

같은 데이터 폴더에서 동시에 실행하지 않습니다. 비정상 종료 후 `data/runner.lock`이 남으면 파일에 적힌 PID의 점검기 프로세스가 종료됐는지 먼저 확인한 뒤 **그 잠금 파일 하나만** 제거하고 재시작합니다. 살아 있는 다른 점검기의 잠금은 제거하지 않습니다.

자동 검사는 정해진 화면 요소와 픽셀 기준의 검사입니다. 모든 시각적 배치 의도, 전시 내용의 정확성, 로그인·결제·저장 기능은 검증하지 않습니다. 3D 소프트웨어 렌더링과 실제 이용자의 GPU 환경은 다를 수 있으며, 비밀번호 전시와 종료 안내는 미확인으로 구분합니다. 공개 URL 방문으로 통상적인 조회수/분석 이벤트가 기록될 수 있습니다.
